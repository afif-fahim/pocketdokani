# Keep order references independent of courier consignments

PocketDokani assigns its own stable order reference (for example `PD-0012`), and courier booking sends it as the courier invoice. Courier consignment identifiers remain separate because a new order's pack check must work before, and without, courier booking. The courier's unique-invoice rule also prevents a second booking for the same order.

The original decision incorrectly assumed that historical seller labels already used PocketDokani references. On November 1, 2026, the seller confirmed that the existing workbook and labels use their original order numbers. Imported historical orders therefore retain that workbook number as their label order number while preserving the app's stable reference. Pack checks compare the label with that explicit source number, allowing an optional decorative `#`; they never substitute an arbitrary courier consignment ID. Orders created in PocketDokani, including constructed judge orders, continue to use their app reference on the label.
