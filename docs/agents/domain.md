# Domain docs

## Before exploring

This repository uses a single-context layout.

- Read root `GLOSSARY.md` for domain vocabulary, when present.
- Read relevant decisions in `docs/adr/`, when present.

If these files are absent, proceed silently. Create them through
domain-modeling when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issues, designs, code, and tests.
If a needed concept is missing, reconsider the terminology or record
the gap for domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, citing the decision
and explaining why it should be reconsidered.
