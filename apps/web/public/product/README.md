# Landing product evidence

Reusable synthetic assets and captions for issue #22 and the documentation handoff to #23. The result images show a local development walkthrough on November 4, 2026, using the actual application and real Meta model calls. The five `parcel-*` gallery scenes other than `parcel-check.jpg` and `parcel-input.png` are AI-generated illustrations of fictional orders: they are not model inputs or app results. None are customer conversations, real parcels, pilot observations or an accuracy evaluation.

## Sources and capture

All walkthrough inputs are constructed development fixtures generated by `apps/api/pocketdokani/demo/fixtures.py` and registered in `evals/split_manifest.json` before any model call (manifest SHA-256 `5bf15c596943e9affac9f27db8602a737fce6cde22aeaeddca2aff5eef6f08ae` after formatting; same source groups as at the run):

- `constructed-conversation-002`: `constructed-chat-screenshot-001` and `constructed-chat-screenshot-002`. The public conversation input is the first screenshot, byte-for-byte identical to the source stored for extraction.
- `constructed-parcel-illustration-002`: `constructed-parcel-scene-wrong-cod` and `constructed-parcel-scene-correct`, both generated by the app for the newly confirmed order `PD-1A17780B2B5A4518`. The public parcel input is the wrong-COD image as uploaded. The illustrated bags are synthetic. The unreadable variant was not run.
- The assistant question was typed against this isolated constructed shop. No audio was submitted and no transcription was tested.

The owner approved this rerun on new inputs. The local stack used a temporary SQLite database and local object storage, a simulated courier, and a finite allowance of 14 provider attempts for the session. The audit records **11 provider attempts: 7 Muse Spark and 4 SAM**, plus one `assistant_turn` orchestration record. Each step ran once, and no result was retried or selected. No courier booking was made in this walkthrough.

The capture browser lost its session cookie after extraction was requested. Extraction finished and saved. To avoid a second model call, the session row in the temporary database was reattached to a new token for the same shop. This did not change any order, draft or result.

Result images are browser captures of the actual app at 430 px width and device scale 2, with sticky navigation hidden. Values, verdicts and record chips were not edited or generated for the landing page. `parcel-check.jpg` joins the top of the result with its COD row; a gap marks the omitted passing rows between them. `order-review.jpg` and `order-quote.jpg` were captured after confirmation and show the same extracted values. Original local records and audits remain ignored; they are not public assets.
