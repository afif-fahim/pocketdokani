# Landing product evidence

Reusable synthetic assets and captions for issue #22 and the documentation handoff to #23. These show a local development walkthrough on November 4, 2026, using the actual application and real Meta model calls. They are not customer conversations, real parcels, pilot observations or an accuracy evaluation.

## Sources and capture

All inputs are constructed development fixtures, registered in `evals/split_manifest.json`:

- `constructed-conversation-001`: `constructed-screenshot-001` and `constructed-screenshot-002`. The public conversation input is the first screenshot, byte-for-byte identical to the source used for extraction.
- `constructed-parcel-illustration`: `constructed-parcel-unreadable`. The parcel input was generated by the existing app for the same newly confirmed order, `PD-0DEF112AC1994D96`. The phone is deliberately obscured. The illustrated bags are synthetic.
- The assistant question was typed against this isolated constructed shop. No audio was submitted and no transcription was tested.

The owner explicitly approved sending this synthetic conversation, one synthetic parcel image and one Bangla shop question to `api.meta.ai`, using the configured server key and a finite allowance of 12 provider attempts. The same question was submitted three times: first with the English answer setting, then with Bangla selected, and once more in Bangla to replace an incorrect screenshot crop. The final answer image comes from the third turn. The audit records **11 provider attempts: 9 Muse Spark and 2 SAM**, within the original allowance. No further calls were made. No real courier booking occurred.

After sign-out, a temporary loopback-only development helper created an ordinary browser session for the same original constructed shop so the stored extraction and parcel check could be captured again. It did not regenerate results or reset the allowance. Protected-record fingerprints confirmed that orders, drafts, source images, pack checks, stock and other business records remained unchanged; only browser sessions, the new assistant audit rows and the expected model-budget usage changed. This was screenshot recovery within the original shop, not session rotation to evade a budget.

Result images are crops of browser captures of the actual app. Values, verdicts and record chips were not edited or generated for the landing page. Input images are source fixtures, not app-result screenshots. Original local records and audits remain ignored; they are not public assets.
